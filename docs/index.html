Getting started

Argon UI is one self-contained Luau file. It needs no host script, no folder layout, and no globals of your own. Load it, create a window, add a tab, and add controls.

local Argon = loadstring(game:HttpGet(
    "https://raw.githubusercontent.com/JirkaachS/argon-ui/main/argon-ui.luau"
))()

local Window = Argon:CreateWindow({
    Name = "My Hub",
    Theme = "Argon",
    ConfigurationSaving = { Enabled = true, FolderName = "MyHub", FileName = "config" },
})

local Tab = Window:CreateTab("Main", "zap")
Tab:CreateSection("Farming")

Tab:CreateToggle({
    Flag = "AutoFarm",
    Name = "Auto farm",
    CurrentValue = false,
    Callback = function(enabled)
        print("auto farm:", enabled)
    end,
})

Argon:LoadConfiguration()
That last line matters. LoadConfiguration restores saved values, reapplies each control's callback, and switches autosave on. Call it once after all controls are built.

Installation

Remote (recommended)

local Argon = loadstring(game:HttpGet(
    "https://raw.githubusercontent.com/JirkaachS/argon-ui/main/argon-ui.luau"
))()

Local file with remote fallback

Useful when you ship the library beside your script and still want automatic updates.

local function loadArgon()
    if isfile and readfile and isfile("argon-ui.luau") then
        local chunk = loadstring(readfile("argon-ui.luau"), "@argon-ui.luau")
        if chunk then return chunk() end
    end
    return loadstring(game:HttpGet(
        "https://raw.githubusercontent.com/JirkaachS/argon-ui/main/argon-ui.luau"
    ))()
end

local Argon = loadArgon()
Environment. Argon UI parents its ScreenGui to CoreGui when the executor allows it and falls back to PlayerGui. Configuration saving needs executor file functions (writefile, readfile, and friends); common syn.* aliases are detected automatically. Without them the UI still works, only persistence is unavailable.

Tabs and sections

Tabs hold sections, and sections group controls. If you add a control before creating a section, Argon UI creates a General section for you.

local Tab = Window:CreateTab("Combat", "swords")

Tab:CreateSection("Targeting")
Tab:CreateToggle({ Name = "Aim assist", Callback = function() end })

-- Section objects build controls directly, which reads well for long tabs.
local Movement = Tab:Section({ Title = "Movement" })
Movement:Slider({ Name = "Walk speed", Range = { 16, 120 }, CurrentValue = 16 })
Movement:Toggle({ Name = "Infinite jump" })

Every Create* method also exists without the prefix (Tab:Toggle, Tab:Slider, Section:Dropdown, …), so both naming styles work.

Section navigation new

A tab with more than one section gets a chip rail under the topbar, one chip per section, and clicking a chip scrolls to it. The strip scrolls horizontally when a tab has more sections than fit, and it steps aside while a search filter is active because a chip that jumps to a filtered-out section is a dead link. Nothing to call: it follows the sections you create. This replaces the old SECTIONS button and its popover, so the organisation of a tab is visible without clicking anything.

Rows

A tab with ninety controls is a single column you scroll blind, and the related ones end up screens apart. A row splits the section body into equal columns and hands controls out round-robin, so the pair you build together sits side by side.

local row = Tab:CreateRow({ Columns = 2 })
row:CreateToggle({ Flag = "Chams", Name = "Chams", CurrentValue = false })
row:CreateSlider({ Flag = "ChamsOpacity", Name = "Opacity %", Range = { 5, 100 }, CurrentValue = 60 })

-- when the pairing matters more than the balance
row:Use(2):CreateToggle({ Name = "Pin me right", CurrentValue = false })

Columns accepts 1 to 4 and may be passed bare (Tab:CreateRow(2)). Spacing sets the gap and MinColumnWidth (default 200) is the width below which columns collapse back into a single stack, so a resized window and a phone get a readable layout from the same calls.

Rows carry the same shorthands as sections, their controls join the owning section for search and the control count, and a row hides itself when everything in it is filtered out. Best suited to compact controls — toggles, sliders, steppers, keybinds, colour pickers, buttons. Dropdowns, inputs, segmented pickers, lists and text areas want the full width.

The mockups below show a two- and three-column group side by side with a full-width row.

What it looks like

Static replicas of the interface, built from the library's own palette and metrics. They exist so you can pick a control by sight instead of by name — each mockup sits beside the call that produces it in the sections below.

For a version you can actually click, the browser preview is a working reimplementation of the whole interface: draggable sliders, a real HSV colour picker, filtering dropdowns, collapsing rows, tooltips, locks, confirmations, and all ten palettes.

The sidebar collapses on narrow viewports and the section body reflows to a single column, which is the same behaviour MinColumnWidth drives for rows.

Every control on a visual line is grown to the height of the tallest, so a slider next to a toggle does not leave a step in the edge of the section.

Segmented new

A compact pill row for two to four mutually exclusive choices. Cheaper to read than a dropdown and requires no popup.

local mode = Tab:CreateSegmented({
    Flag = "FarmMode",
    Name = "Farm mode",
    Options = { "Safe", "Balanced", "Fast" },
    CurrentOption = "Balanced",
    Callback = function(value) setFarmMode(value) end,
})

mode:Set("Fast")
mode:Refresh({ "Safe", "Fast" })   -- rebuilds the strip
print(mode.CurrentValue)           -- "Fast"

Tooltips

A tooltip costs no row height, which is why the marker exists: without it there is nothing to tell you hovering would say more. The panel wraps to its content, opens after a short delay, and flips to the other side or below the row rather than covering it.

Locks

A lock states the precondition up front instead of letting the click fail. Use it for dependent settings and for pairs that cannot run together.

Configuration and persistence

Give a control a Flag and it becomes part of the saved configuration. Values are written to FolderName/FileName about a third of a second after a change, and every write is read back and verified.

local Window = Argon:CreateWindow({
    Name = "My Hub",
    ConfigurationSaving = {
        Enabled = true,
        FolderName = "MyHub",
        FileName = "config-" .. tostring(game.Players.LocalPlayer.UserId),
    },
})

-- build every tab and control first, then:
local ok, info = Argon:LoadConfiguration()
if not ok then warn("config:", info) end

How loading behaves

Callbacks always run

A stored value equal to the control default still reapplies its behavior, so features cannot silently stay off.

Autosave turns itself on

Persistence activates after loading, or shortly after CreateWindow if you never load.

Unknown flags survive

Values for controls that do not exist yet are kept, applied when that flag registers, and never dropped on save.

Writes are verified

Saves re-read the file and return false, reason when the contents do not match.

Order matters. Create controls before calling LoadConfiguration. Flags that arrive later still hydrate, but loading last keeps startup deterministic.

Working with values directly

print(Argon:GetFlagValue("AutoFarm"))
Argon:SetFlagValue("FlySpeed", 220)      -- applies and saves
local everything = Argon:GetFlags()       -- flag -> value snapshot

local unbind = Argon:OnFlagChanged(function(flag, value)
    print("changed:", flag, value)
end)
unbind()                                  -- stop listening

local stats = Argon:GetConfigurationStats()
print(stats.Path, stats.Ready, stats.PendingFlags, stats.LastError)

Resetting

Argon:SaveConfiguration()     -- returns ok, path
Argon:DeleteConfiguration()   -- removes the file
Argon:ResetConfiguration()    -- clears stored values and deletes the file
Multiple accounts or presets. Put the identifier in FileName. Separate files never overwrite each other, which avoids the classic “settings keep resetting” problem when two builds share one file.

Themes

Ten built-in palettes: Argon, Amethyst, Midnight, Emerald, Rose, Slate, Ember, Nord, Mono, and Ocean. Theme changes apply live to existing controls.

The topbar picker new

Every window gets a palette button in the topbar. It wears the current theme instead of an icon — three overlapping AccentLight / Accent / AccentDark dots — so it doubles as a readout of what is active. Clicking it opens a grid of every registered theme, each swatch previewing its own palette, with the active one outlined in its accent.

-- Shown by default. Hide it on a window that owns its own theming UI.
local Window = Argon:CreateWindow({ Name = "My Hub", ThemePicker = false })

Window:SetThemePickerVisible(true)   -- bring it back
Window:ToggleThemePicker()           -- open or close the panel; returns the new state
It persists on its own. When CreateLibrarySettings is present the picker writes through that tab's ArgonUITheme flag, so the dropdown stays in step and the choice survives the next LoadConfiguration.
print(Argon:GetThemes())
Window:SetTheme("Midnight")

Argon:AddTheme("Slate", {
    Background = Color3.fromRGB(9, 11, 14),
    Window     = Color3.fromRGB(14, 17, 22),
    Surface    = Color3.fromRGB(21, 26, 33),
    Accent     = Color3.fromRGB(120, 190, 255),
    Text       = Color3.fromRGB(238, 244, 250),
})
Argon:SetTheme("Slate")

A palette may define any of Background, Window, Sidebar, Surface, Hover, Active, Input, Border, BorderSoft, Text, Muted, Dim, Accent, AccentLight, AccentDark, Success, Warning, and Danger. Missing keys inherit the default theme.

Controls repaint even when they were hovered or mid-animation at the moment the theme changed. Frames your own script builds sit outside the library, so read the live palette rather than baking colours in.

row.BackgroundColor3 = Argon:GetColor("Surface")

local unbind = Argon:OnThemeChanged(function(palette, themeName)
    row.BackgroundColor3 = palette.Surface
end)

Overlays, dialogs, and the settings tab

Overlays

Two draggable overlays ship with the window: a player list and an active-keybind panel. Their positions persist, and they can be pinned so they stay on screen after the main window is hidden.

Window:SetPlayerListVisible(true)
Window:ToggleKeybindList()
Window:SetOverlayTransparency(0.3)   -- 0.12–0.8
Window:SetOverlayScale(1.1)          -- 0.75–1.4
Window:ResetOverlayPositions()

-- Keep them visible while the interface is hidden.
Window:SetOverlaysAlwaysVisible(true)
Window:ToggleOverlaysAlwaysVisible()
print(Window:AreOverlaysAlwaysVisible())

Pass OverlaysAlwaysVisible = true to CreateWindow to start pinned. The preference is saved with the configuration, and CreateLibrarySettings adds a Keep Overlays On Screen toggle plus hotkeys that toggle each overlay while the menu is closed.

Dialogs

Window:Dialog({
    Title = "Delete profile?",
    Content = "This cannot be undone.",
    Buttons = {
        { Title = "Cancel" },
        { Title = "Delete", Variant = "Danger", Callback = function() deleteProfile() end },
    },
})

-- Shorthand for the two-button destructive case.
Window:Confirm({
    Title = "Delete profile?",
    Content = "“Farming” and its saved settings will be removed.",
    ConfirmText = "Delete",
    OnConfirm = function() deleteProfile("Farming") end,
})

Confirm defaults to cancel, tints the confirm button as a danger, guards against a double click, and destroys the overlay once a choice is made. Worth wiring to anything that deletes, withdraws everything, or resets state.

Built-in settings tab

One call adds theme, overlay, logo, and transition controls, all flagged and persisted for you.

local Settings = Window:CreateTab("Settings", "settings")
Window:CreateLibrarySettings(Settings)

Notifications

Argon:Notify({ Title = "Saved", Content = "Configuration written.", Duration = 4 })

The accent and the icon come from the title: titles containing error or failed read red, warn or wait amber, and success, complete or saved green. Everything else uses the accent.

They do not hide with the window. The toast layer lives on the ScreenGui rather than inside the window frame, because a notification that only appears while the menu happens to be open cannot report what a background feature just did. The card grows to fit its body instead of clipping at a fixed height, and the stack is capped at five so a burst cannot run off the bottom of the screen.

Library API

Argon:CreateWindow(options) → window

Creates the interface shell. See Windows for options.

Argon:Notify(options)

Shows a toast: Title, Content, Duration.

Argon:SetTheme(name) → ok, err

Applies a built-in name or palette table to every live control.

Argon:GetThemes() → table

Sorted list of registered theme names.

Argon:AddTheme(name, palette)

Registers a custom palette. Unspecified keys inherit defaults.

Argon:GetColor(key, fallback) → Color3

Reads one key from the active palette. Returns fallback when the key is unknown.

Argon:GetPalette() → table

Detached snapshot of the active palette. Argon.Palette is the live table.

Argon:OnThemeChanged(callback) → unbind

Calls callback(palette, themeName) after every theme change, for GUIs the library does not own. Call the returned function to unbind.

Window:Confirm(options) → dialog

One-shot confirmation for destructive actions. Title, Content, ConfirmText, CancelText, OnConfirm, OnCancel. Cancel is the default, the confirm button is tinted as a danger, and the dialog destroys itself once a choice is made.

element:SetTooltip(text)

Hover text that costs no row height. Also settable as Tooltip in any control config. Marks the control with a ? after its title and sets element.HasTooltip. The panel wraps, sizes to its content and anchors beside the row rather than under the cursor, flipping side or stacking above/below when there is no room.

element:Lock(reason) · Unlock() · SetLocked(locked, reason)

States a precondition on the control instead of failing after the click. The row is dimmed and gets a padlock badge carrying the reason, collapsing to LOCKED and then to the padlock alone on a narrow column so the title stays readable. Locking again only updates the reason.

Argon:SaveConfiguration() → ok, pathOrReason

Writes and verifies the configuration file immediately.

Argon:LoadConfiguration() → ok, warningOrReason

Restores values, reapplies callbacks, and enables autosave. Returns a warning string when some flags failed or are unknown.

Argon:DeleteConfiguration() → ok, pathOrReason

Removes the configuration file if the executor exposes delfile.

Argon:ResetConfiguration() → ok, reason

Clears pending values and deletes the file while suppressing a queued autosave.

Argon:SetPersistenceReady(value[, saveNow]) → ok

Manual autosave gate. Optional now that loading enables persistence automatically; still useful to suppress writes during a long startup.

Argon:GetFlagValue(flag) → value

Reads a live control value, or a stored value whose control is not built yet.

Argon:SetFlagValue(flag, value) → ok, reason

Applies a value through the control (running its callback) or parks it for later registration.

Argon:GetFlags() → table

Snapshot of every flag value, including pending ones.

Argon:OnFlagChanged(callback) → unbind

Called with (flag, value, element) on user edits and restores. Returns a function that removes the listener.

Argon:GetConfigurationStats() → table

Path, Enabled, Ready, Loading, RegisteredFlags, PendingFlags, LastError, LastAutosaveError, LastSaveAt, LastLoadAt, LastLoad.

Argon:Destroy()

Saves, disconnects everything, and removes all windows.

Argon.Flags · Argon.Version · Argon.CurrentTheme

Flags maps flag names to control objects, which keeps profile-reset helpers simple.

Recipes

Progress-reporting task

local bar = Tab:CreateProgressBar({ Name = "Scan", Maximum = #targets })
local log = Tab:CreateList({ Name = "Results", Height = 150, EmptyText = "Nothing found yet" })

Tab:CreateButton({ Name = "Start scan", Callback = function()
    task.spawn(function()
        for index, target in ipairs(targets) do
            bar:Set(index)
            if inspect(target) then log:AddItem({ Title = target.Name, Description = "match" }) end
            task.wait()
        end
        Argon:Notify({ Title = "Scan complete", Content = ("%d results"):format(#log.Items) })
    end)
end })

Mirror settings into your own config table

task.spawn(function()
    while true do
        local stats = Argon:GetConfigurationStats()
        card:SetContent(("%s · %d flags · %d pending"):format(

Migrating from Rayfield-style scripts

The window, tab, control, flag, notification, and configuration calls keep the same shapes, so most menus only need their loader swapped.

-- before
local Rayfield = loadstring(game:HttpGet("https://sirius.menu/rayfield"))()

-- after: the rest of the script can stay as it is
local Rayfield = loadstring(game:HttpGet(
    "https://raw.githubusercontent.com/JirkaachS/argon-ui/main/argon-ui.luau"
))()

Save resultsSaveConfiguration returns ok, path or ok, reason instead of only a boolean.
SectionsOptional grouping layer with its own builders.

Tests

The repository ships a functional suite that runs the real library outside Roblox against a small Roblox API sandbox, so control logic and persistence are verified without launching a game.

# requires https://github.com/lune-org/lune
lune run tests/run.luau

246 checks cover every control, rows and their line-height balancing, tooltips and locks, the configuration round-trip, deferred flag hydration, dropdown restore timing, debounced autosave, themes, dialogs, and window controls. The sandbox models API surface rather than rendering, so layout and input still need a real client.

Changelog

1.16.0

  • Typography. The whole interface renders in BuilderSans, Roblox's own modern UI family. Measured in a live client it draws the same string about 13% narrower than GothamSSm at the same size, so titles fit where they used to truncate. TextButtons and TextBoxes get the font face too; before, only labels did, so half the interface used the legacy raster face.
  • Text controls scale with their text. Label, Paragraph and TelemetryCard were fixed-height rows with a fixed-height text slot on a root that clips, so anything past two short lines was cut off and a short value left dead space behind. All three are laid out now and are exactly as tall as their content.
  • Inputs reworked. A recessed well with a focus ring and a clear button. A long value is elided while the field is unfocused — the scheme is dropped and the informative head and tail are kept — and the real text returns for editing on focus. CurrentValue is always the full string.
  • Notifications no longer hide with the window, which is the case that actually matters for reporting what a background feature just did. Rebuilt as a card that grows to fit its body, with a severity glyph, a tinted icon plate, a hover-lit close button and a timer that cannot draw across the rounded corners. The stack is capped at five.
  • Section navigation moved out of the SECTIONS popover into an always-visible chip rail under the topbar. It scrolls horizontally when a tab has many sections and steps aside while a search filter is active.
  • The live indicator is tinted with Success, sizes to its own label, and has a slow breathing halo instead of being a grey capsule with a dot in it.
  • Fixed: square window corners. ClipsDescendants clips children to the rectangle, not to the UICorner, so the decorative glow painted straight into the rounded corners — worst at the top right, where the larger glow sits. The glow layer and the loader are composited groups now, so they stop at the rounded edge.
  • Fixed: the selected tab ignored a theme. Its button, icon plate and title are painted from selection state, so the repaint pass pushed all three back to the inactive palette entry. On startup with a saved theme the selected tab kept the default accent while everything around it had moved on.

1.15.0

  • A theme picker in the topbar: a palette button wearing the active accent, opening a grid of every registered theme with per-theme swatch previews. ThemePicker, SetThemePickerVisible, and ToggleThemePicker control it, and it writes through the ArgonUITheme flag so the choice persists.
  • Fixed row layout re-entrancy: relayout writes the row's size and was also listening to that frame's AbsoluteSize, so every write re-entered the handler until Roblox aborted it. One live session logged 212 Maximum event re-entrancy depth exceeded errors; it now logs none.

1.14.0

  • Locked controls now show a self-contained padlock badge instead of a plain scrim, collapsing from the full reason to LOCKED to the padlock alone as the column narrows.
  • Rows balance line heights: every control on a visual line grows to the tallest, so a slider beside a toggle no longer leaves a step in the section edge.

1.13.1

  • A ? marker after the title makes tooltip-bearing controls discoverable, and element.HasTooltip exposes the same fact to code.
  • Tooltips anchor beside the control instead of following the cursor, flipping side or dropping below the row rather than covering it.

1.13.0

  • SetTooltip and the Tooltip option: hover help that costs no row height.
  • Window:Confirm for destructive actions, plus a Danger dialog variant and body text that measures its own wrapping.
  • Lock, Unlock, and SetLocked state a precondition up front instead of letting the click fail.

1.12.0

  • List rows accept several Actions with danger and warning tints, not just one.
  • Fixed descriptions and state colours: a control restored from configuration now paints its active colour, not only its value.

1.11.0

  • CreateRow and Section:Row put several controls on one line, round-robin across equal columns, collapsing to a stack below MinColumnWidth.

1.10.0

  • SetTheme repaints every bound property unconditionally, so hovered or mid-tween controls no longer stay on the previous palette.
  • New palette API: Argon.Palette, GetColor, GetPalette, and OnThemeChanged for GUIs the library does not own.
  • Sliders and progress bars got a recessed groove with a soft border, a fill that terminates under the knob, and corrected drag mapping.

1.9.0

  • Real Lucide icons, sharper text rendering, and ten built-in themes.
  • Fixed control descriptions and the active-keybind overlay.

1.8.1

  • Overlays can stay on screen while the main window is hidden, with SetOverlaysAlwaysVisible, ToggleOverlaysAlwaysVisible, AreOverlaysAlwaysVisible, and an OverlaysAlwaysVisible window option.
  • The preference persists, and the library settings tab gained a pin toggle plus hotkeys for each overlay.

1.8.0

  • Standalone hardening: configurable GuiName, neutral default folder and titles, and no assumptions about any host script.
  • New components: ProgressBar, Stepper, Segmented, TextArea, and List.

  • FileName now respects a custom extension instead of always appending .rfld.

1.7.0

  • Values for controls that do not exist yet are retained, hydrated later, and preserved on save.
  • Dropdowns remember a requested selection while their options are empty or filtered.
