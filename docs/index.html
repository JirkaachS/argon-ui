Roblox Luau UI library · 2.0

Argon UI

A single-file UI library for Roblox Luau scripts. It gives you a window with tabs, sections and 22 control builders, a command palette, change tracking with undo, configuration profiles, notifications, twelve themes, and full mouse, keyboard, touch and gamepad support. The API follows Rayfield's, so most existing menus only need their loader swapped.

Getting started

Argon UI is one self-contained Luau file. It needs no host script, no folder layout and no globals of your own. Load it, create a window, add a tab, and add controls.

local Argon = loadstring(game:HttpGet(
    "https://raw.githubusercontent.com/JirkaachS/argon-ui/main/argon-ui.luau"
))()

local Window = Argon:CreateWindow({
    Name = "My Hub",
    Theme = "Argon",
    ConfigurationSaving = { Enabled = true, FolderName = "MyHub", FileName = "config" },
})

local Main = Window:CreateTab("Main", "zap", { Group = "Farming" })
Main:CreateSection("Auto farm")

Main:CreateToggle({
    Flag = "AutoFarm",
    Name = "Auto farm",
    Description = "Collects drops and finishes quest steps.",
    CurrentValue = false,
    Keybind = "F",   -- optional: pressing F flips it
    Callback = function(enabled)
        print("auto farm:", enabled)
    end,
})

Window:CreateLibrarySettings(Window:CreateTab("Settings", "settings"))
Argon:LoadConfiguration()
That last line matters. LoadConfiguration restores saved values, runs each restored control's callback once, and turns autosave on. Call it once, after your controls are built. You do not need to open the window yourself: it opens when your script finishes.

Installation

Remote (recommended)

local Argon = loadstring(game:HttpGet(
    "https://raw.githubusercontent.com/JirkaachS/argon-ui/main/argon-ui.luau"
))()

Local file with remote fallback

Useful when you ship the library beside your script and still want updates.

local function loadArgon()
    if isfile and readfile and isfile("argon-ui.luau") then
        local chunk = loadstring(readfile("argon-ui.luau"), "@argon-ui.luau")
        if chunk then return chunk() end
    end
    return loadstring(game:HttpGet(
        "https://raw.githubusercontent.com/JirkaachS/argon-ui/main/argon-ui.luau"
    ))()
end

local Argon = loadArgon()
Environment. The window goes into gethui(), CoreGui or PlayerGui, whichever is available. After the one HttpGet that fetches the file, the library makes no network requests while it loads: all 1,573 icons are built in and the avatar is an rbxthumb:// URL. Configuration saving needs the executor's file functions (writefile, readfile, isfile); without them the interface works and simply does not persist.

The source lives in src/ as about 80 small modules. build.luau bundles them into the single argon-ui.luau you load, so loadstring(game:HttpGet(url))() keeps working.

What's new in 2.0

Argon UI 2 is a rebuild. The public API is source-compatible with 1.18: every method, alias, option key, callback payload and saved-value format still works, and 1.x configuration files load unchanged. What is different:

Speed

Nothing slow before the first frame

No icon download, no avatar lookup and no base64 decode at load. Create* records state; the visible tab is built first in small slices, the rest after the window opens. Nothing runs while idle.

 Loader

A loader without fixed timers

A quick script opens with no loader card. A big one shows what is really happening, "Building Combat · 155 of 212", and opens when the work is done.

 Look

Glass frame, solid content

A tinted frame around an opaque sheet, one platter per section, Montserrat headings over Roboto rows, 12 themes, an accent override, three materials, scale and density.

 Find

Command palette

Ctrl+K, / or gamepad Y. Finds controls in tabs that were never opened; Enter goes, Ctrl+Enter runs in place, Left and Right adjust.

 Undo

Change tracking and undo

Changed rows get a dot, tabs and sections reset, and Ctrl+Z or the Undo pill brings the values back.

 Menu

Row menu

Right-click, long-press, Shift+F10 or gamepad X on any row: reset, copy and paste the value, copy the flag, pin, show in palette.

 Profiles

Named configurations

Save, load, rename and delete profiles, pick one to load on start, and share them as an ARGON2: code.

 Notify

Notifications with actions

Types, up to two buttons, progress, update in place, an inbox behind the bell, and errors from your callbacks shown with Copy error and Retry.

 Pins

Pins and quick dock

Pinned switches and buttons stay reachable in the sidebar and in a dock that remains on screen while the window is hidden.

 Input

Keyboard and gamepad

A focus ring, arrow-key navigation and adjustment, Ctrl+1-9 for tabs, a gamepad hint bar. Backspace and pad B close the top layer.

 Controls

New blocks

Callout, Stat with a sparkline, Image, ButtonGroup, Checkbox, button variants and Keybind = "F" on toggles and buttons.

 Gate

Key system

Rayfield's KeySystem and KeySettings, plus Validate and GetKeyLink, shown as a card before the window opens.

The complete list is in the changelog, and measured numbers against 1.x are in bench/RESULTS.md.

Upgrading from 1.x

Replace the file. Your script and your users' saved configuration files keep working. These are the changes you might notice; each one is deliberate:

  1. There is no pill loader and no 0.93 s minimum. A quick script opens with no loader card, and the window opens when your script is done.
  2. The player list and keybind list overlays are off unless you enable them (PlayerList = true, KeybindList = true, or the setters). The keybind list shows every bind (active ones highlighted) and hides when there are none.
  3. A Keybind whose config has Callback but no OnPressed/Pressed now calls Callback() on press, as Rayfield does (with HoldToInteract, Callback(true) on press and Callback(false) on release). Rebinds fire OnChanged(key). Scripts that used Callback as a rebind listener should add CallOnChange = true or use OnChanged. Configs with OnPressed keep the 1.x behaviour.
  4. Escape no longer clears a keybind during capture (Backspace or Delete do) and is never a close key, because Escape opens Roblox's own menu. Backspace and gamepad B close the top layer.
  5. A notification's Type overrides the guess from its title, and the guess now matches whole words ("No errors found" is not an error).
  6. No ALL CAPS: section headers, the subtitle and loader status show your text as given. The "LIVE" pill and the "ARGON / TAB" eyebrow are gone (Window:SetStatus adds a status chip if you want one).
  7. Dropdown:Set("unknown") keeps the current selection instead of clearing it.
  8. Input fires its callback on Enter even when the text did not change, and RemoveTextAfterFocusLost fires once and keeps the submitted text as CurrentValue.
  9. Controls in a row no longer pad each other to equal height; _balance() and _relayout() are no-ops.
  10. A slider suffix that is a word gets a space ("10 Bananas"); short suffixes stay attached ("50%", "3ms").
  11. PruneRegistries() returns zero counts: there are no global registries left to prune. Argon._themeBindings and Argon._connections stay as empty tables.
  12. The library settings rows are views over the window preferences instead of flags. The 1.x ArgonUI* flag names still work through GetFlagValue and SetFlagValue.
  13. Window size: the default is max(min(gui - 160, 1080), min(720, gui - 16)) wide by max(min(gui - 110, 700), min(440, gui - 16)) tall; the sidebar is 232 px and collapses to a 64 px icon rail.
  14. LoadConfiguration() returns true (with an info string) when there is no saved file yet, and when every value is parked for controls that do not exist yet.
  15. SetTheme(table) is remembered as a custom theme across sessions. Theme changes made from the picker are saved.
  16. OnFlagChanged unbinds by identity, so unbinding one listener never removes another.
  17. Element:Destroy() releases the flag (its last value is kept for the next save) and any keybinds the control owned.
  18. SetVisible(false) survives tab switches and search.
  19. Lock and SetDisabled block every user path, including a control's keybind; a script's Set still works.
  20. Closing a confirmation with x, the close key or an outside click calls OnCancel.
  21. Colour values read from configuration files without the __argonColor marker are treated as 0-255 (Rayfield's format).
  22. Reading a colour from an instance of a hidden tab right after a theme switch can return the old colour until that tab is shown; read Argon:GetColor or Argon:GetPalette() instead of instance colours.
  23. Overlay transparency (0.12-0.8 in 1.x) now maps onto the frosted HUD range, so overlays stay readable.
  24. SetSmoothTransitions(false) turns on reduced motion.
  25. Technical keeps Sarpanch; the default typeface is still Roboto with Montserrat headings (BuilderSans is one of the six sets).
Palette keys. The 1.x theme keys Background, Window, Sidebar, Input, AccentLight and AccentDark still work as aliases of the 2.0 tokens, for reading (GetColor, OnThemeChanged) and for writing (AddTheme, SetTheme(table)). See Themes.

Showing and hiding

Insert (or your ToggleUIKeybind) hides and shows the window. The first time a user hides it, a notice says how to bring it back ("My Hub is hidden. Press Insert to reopen"). While it is hidden, touch devices get a reopen orb on the left edge and PC gets a dock pill when OpenButton asks for one; both can be dragged and snap to the nearest edge. Pinned controls sit next to them.

Window:SetVisibility(false)      -- also Open(), Close(), Toggle(), ToggleVisibility()
print(Window:IsVisible())
Window:SetToggleKey(Enum.KeyCode.RightShift)
Window:SetOpenButton("always")   -- "auto", "always" or "off"
Window:SetMouseUnlock(false)     -- keep the cursor locked in first-person games

Cursor

Some games draw their own pointer: they set UserInputService.MouseIconEnabled to false and render an image in PlayerGui. PlayerGui sits below CoreGui, so that pointer disappears behind the window and you end up clicking blind. When the engine cursor is off, Argon draws its own above everything it owns.

Argon:CreateWindow({ Name = "My Hub", Cursor = "auto" })  -- default
Window:SetCursorVisible(false)   -- never draw one
Window:SetCursorVisible(true)    -- always draw one
Window:SetCursorVisible()        -- back to automatic detection
print(Window:IsCursorDrawn())

Loading

You do not have to do anything. While your script builds, the window stays hidden; it opens as soon as one of these is true: your script finished, it called FinishLoading, or it has built a tab and gone quiet for 250 ms. Nothing is shown for the first 150 ms, so a quick script opens with no loader card at all. A card appears only while real work is still pending, says what it is doing, and hands over to the already-built window with a short morph.

Your scriptWhat happens
Builds everything in one goThe window opens in about 0.1 to 0.2 s with no card.
Builds, then calls LoadConfigurationThe card appears at 150 ms showing "Restoring settings · 72 of 96" and the window opens when the restore ends.
Waits (an HttpGet, WaitForChild) before creating any tabThe card shows "Waiting for script"; after 8 s without progress it offers Open now and Copy log.
Waits in the middle of the buildAfter 250 ms of quiet the window opens with the tabs built so far; later tabs slide into the sidebar.
Uses Loading = "manual" and never finishesThe stall footer appears at 8 s, and the window opens by itself 30 s after the last progress report.

Driving the loader yourself

Declare manual mode in the options, report progress, and finish. Progress never goes backwards: a lower value than the last one is ignored.

local Window = Argon:CreateWindow({ Name = "My Hub", Loading = "manual" })

for index, spec in ipairs(tabsToBuild) do
    Window:SetLoadingProgress(index / #tabsToBuild, "Building " .. spec.Name)
    buildTab(spec)
end

Argon:LoadConfiguration()
Window:FinishLoading()   -- the window opens with the restored values already on screen
-- Runs your builder under xpcall: an error is shown on the loader card
-- with Open anyway and Copy error instead of leaving a half-built window.
Window:Build(function(window)
    local Combat = window:CreateTab("Combat", "swords")
    -- ...
end)

Window:OnLoaded(function()
    Argon:Notify({ Title = "Ready", Content = "Press Insert to hide the menu.", Type = "info" })
end)

Key system

An opt-in key gate with Rayfield's option names. The card is drawn before anything waits, then CreateWindow waits for a valid key; this is the one documented yield in CreateWindow. A wrong key shakes the card and shows the reason; a remembered key skips the gate next time.

local Window = Argon:CreateWindow({
    Name = "My Hub",
    KeySystem = true,
    KeySettings = {
        Title = "My Hub",
        Subtitle = "Enter your key to continue",
        Note = "Keys are free: open the link, then paste the key here.",
        FileName = "MyHubKey",       -- remembered as FolderName/MyHubKey.key
        SaveKey = true,
        Key = { "alpha-2024", "beta-2024" },
    },
    GetKeyLink = "https://example.com/key",
    -- Or check keys yourself; return false plus a message to reject:
    -- Validate = function(key) return checkKeyOnServer(key) end,
})

KeySettings.GrabKeyFromSite = true treats each Key entry as a URL and fetches the valid keys in a separate thread. Validate(key) runs in its own thread too, and the Continue button shows "Checking…" while it runs; it returns true to accept, or false, message to reject with your message. Both Validate and GetKeyLink may also be given inside KeySettings.

Tabs and sections

Tabs hold sections, and sections hold controls. If you add a control before creating a section, a General section is created for you.

local Combat = Window:CreateTab("Combat", "swords", {
    Group = "Main",                        -- a caption in the sidebar
    Description = "Aim, targeting and session stats.",
})

Combat:CreateSection("Targeting")
Combat:CreateToggle({ Name = "Aim assist", Callback = function() end })

-- Section objects build controls directly, which reads well for long tabs.
local Movement = Combat:Section({ Title = "Movement", Icon = "move", Collapsible = true })
Movement:Slider({ Name = "Walk speed", Range = { 16, 120 }, CurrentValue = 16 })
Movement:Toggle({ Name = "Infinite jump" })

Combat:SetBadge(3)          -- a count, "New", true for a dot, or nil to clear
Window:SelectTab("Combat")  -- a tab object, its name or its index

Every Create* method also exists without the prefix (Tab:Toggle, Tab:Slider, Section:Dropdown, and so on), so both naming styles work. The third argument of CreateTab is optional, and a table in place of the second argument also works: CreateTab("Combat", { Icon = "swords", Group = "Main" }).

Section navigation

Long tabs get section navigation with nothing to call. In the wide layout an "On this page" list sits to the right of the page and follows the scroll; in the standard, rail and phone layouts a row of section chips sits under the page title once a tab has three or more sections. Clicking either scrolls to that section.

Rows

A row splits a section into equal columns and hands controls out round-robin, so the pair you build together sits side by side. It suits stat tiles, button groups and compact controls such as toggles, sliders, steppers and keybinds; lists and text areas want the full width.

local row = Tab:CreateRow({ Columns = 2 })
row:CreateToggle({ Flag = "Chams", Name = "Chams", CurrentValue = false })
row:CreateSlider({ Flag = "ChamsOpacity", Name = "Opacity %", Range = { 5, 100 }, CurrentValue = 60 })

-- when the pairing matters more than the balance
row:Use(2):CreateToggle({ Name = "Pin me right", CurrentValue = false })

Columns accepts 1 to 4 and may be passed bare (Tab:CreateRow(2)). Spacing sets the gap and MinColumnWidth (default 200) is the width below which the columns stack, so a resized window and a phone get a readable layout from the same calls. On phones rows always stack. Controls in a row keep their own height; 1.x padded them to equal heights, and _balance() and _relayout() are now no-ops.

What it looks like

These are drawings of the interface made with the library's own tokens and metrics, so you can pick a control by sight; each one sits next to the call that produces it further down. They follow this page's colour scheme: the Argon theme in dark mode and Daylight in light mode.

For a version you can click, the browser preview rebuilds the whole interface in HTML: sliders drag, the colour picker has a real HSV square, the palette searches, rows wrap as the window narrows, and all twelve themes apply live.

Only the frame is see-through, and it carries only Text and Text2; everything with dense text sits on the opaque sheet or on opaque platters, so the game behind the window never makes a label hard to read. The accent appears only on what is on, selected, focused or primary.

TextArea

Multi-line entry for lists, notes and payloads. GetLines returns the non-empty lines, which suits "one item per line" input. It always sits under its label at full width.

local filter = Tab:CreateTextArea({
    Flag = "ItemFilter",
    Name = "Item filter",
    PlaceholderText = "One item per line…",
    AutoGrow = true, MinHeight = 80, MaxHeight = 240,
    MaxLength = 500,
    Callback = function(text) print(#text, "characters") end,
})

for _, line in ipairs(filter:GetLines()) do
    print("filter:", line)
end

Height sets a fixed height instead of AutoGrow. Monospace = true uses Roboto Mono for the text. It commits when it loses focus.

Callback timing changed in 2.0. Give a control a Flag and it becomes part of the saved configuration. Values are written to FolderName/FileName shortly after a change, and every write is read back to confirm it landed. 1.x configuration files load unchanged.

local ok, info = Argon:LoadConfiguration()

How loading behaves

Callbacks run once

A restored value runs its callback once, even when it equals the control default, so a feature cannot silently stay off.

Autosave turns itself on

Persistence starts after loading, or a few seconds after CreateWindow if you never load.

Unknown flags survive

Values for controls that do not exist yet are kept, applied when that flag appears, and never dropped on save.

Writes are verified

Saves read the file back and return false, reason when the contents do not match.

LoadConfiguration() returns true (with an info string) when there is no saved file yet, and when every value is waiting for a control that does not exist yet. Colour values in a file without the __argonColor marker are read as 0-255, which is Rayfield's format. Window preferences (theme, accent, scale, size and position, overlays, pins) are kept in a small .meta.json file next to the configuration, or in ArgonUI/<GuiName>.meta.json when saving is off, so they survive even without ConfigurationSaving.

Performance

2.0 was rebuilt for hubs with hundreds of controls. What that means in practice:

  • Nothing slow happens before the window can draw. No icon download or parse, no avatar lookup, no base64 decode, no file write at load.
  • Controls are state first. A Create* call records the control in microseconds. Instances are built by a scheduler that spends a few milliseconds per frame: the visible tab first, the others in the background after the window opens.
  • No slowdown as the hub grows. 1.x scanned every colour against the palette and kept an ever-growing global list, so tab 30 built 7 to 11 times slower than tab 1. 2.0 keeps themed properties per component.
  • Nothing runs at idle. One input handler per library, no per-frame work, no endless tweens and no periodic cleanup.
